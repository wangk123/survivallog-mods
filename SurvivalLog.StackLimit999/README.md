# 生存日志 StackLimit999 Mod（v2.9.21）

《生存日志》(Steam AppID 4164790) 的 BepInEx 6 (IL2CPP) 插件。
**不修改任何游戏文件**，删除插件即完全卸载，不影响存档。

## 功能一览

| 功能 | 效果 | 用法 |
|---|---|---|
| 物品堆叠上限 999 | 同类物品自动堆到 999/格（多次使用食物除外，见下） | 自动生效 |
| 负重上限 ×100 | 背包负重上限放大 100 倍（普通背包约 960Kg） | 自动生效 |
| 拖拽合并 | 把物品拖到同类堆上自动合并（含跨容器：拖到柜子里同种物品上） | 拖拽即可，合并结果落在你拖放的格子上 |
| 一键整理合并 | 点「整理」时先把同类堆合并再整理 | 点背包整理按钮，约 0.3 秒后自动完成 |
| 拆分 | 从堆里拆出指定数量 | **Shift + 左键**点击物品堆（背包/柜子/工作台/无人机交易界面均生效；右键快速转移保留原版） |

## 烹饪 / 多次使用物品（重要）

游戏原生的烹饪预拆分依赖物品配置的堆叠上限 = 1（反汇编实证）。
因此本插件把物品分为两类：

- **多次使用的物品**（如野兔 3 次、脱水胡萝卜 2 次、大米 7 次）：
  保持官方单份状态——**不堆叠、不合并**。放入烹饪区时官方会自动预拆"1 次使用"，
  烹饪一次消耗 1 次使用，取消烹饪原生返还，与原版行为完全一致。
- **单次使用的物品**（如梳打饼干、卤蛋，总次数上限 = 1）与普通物资：
  照常堆叠 999、可合并。"1 份 = 1 次使用"，烹饪/食用按个数消耗即按使用消耗，行为正确。

判定看的是物品的**总使用次数上限**，不是当前剩余次数——多次使用物品哪怕只剩 1 次
也不会被当作单次物品堆叠。

## 安装

### 第一次安装（压缩包里带了全部所需文件）

1. Steam 里右键游戏 → 管理 → 浏览本地文件，打开游戏根目录
   （形如 `...\steamapps\common\Survival Log`）
2. 把压缩包里的**全部内容**解压到游戏根目录，保持目录结构合并：
   - `winhttp.dll`、`doorstop_config.ini` → 游戏根目录
   - `BepInEx\core\`（框架）、`BepInEx\plugins\SurvivalLog.StackLimit999.dll`（本插件）
3. 通过 **Steam 启动**游戏（不要直接双击 exe，会被 Steamworks 检测拒绝）
4. 首次启动会在 `BepInEx\interop` 自动生成约 125MB 的文件，属正常现象，稍等即可

### 只更新插件

关闭游戏后，覆盖 `BepInEx\plugins\SurvivalLog.StackLimit999.dll` 一个文件即可
（游戏运行中会锁定 DLL，覆盖会静默失败）。

## 配置文件

`BepInEx\config\com.local.survivallog.stacklimit999.cfg`
（首次启动游戏后自动生成；**修改后需重启游戏生效**）

| 配置项 | 默认 | 说明 |
|---|---|---|
| StackLimit | 999 | **物品堆叠上限**，可改 1~999999（多次使用食物不受此项影响，恒为官方单份） |
| Mode | All | All=全部物品可堆叠；OnlyStackable=只改原版可堆叠的 |
| BurdenMultiplier | 100 | **负重上限倍数**：原版负重 × 该倍数（100 倍 ≈ 960Kg），1 或 0 = 不修改 |
| MergeOnSort | true | 一键整理时先合并同类（可关） |
| DragMerge | true | 拖拽合并（可关） |
| SplitOnKey | true | Shift+左键拆分（可关） |
| SplitCount | 1 | 每次拆分的数量（0 = 拆一半） |
| ExcludedItemIds | （空） | 不改堆叠上限的物品 ID，逗号分隔 |
| ExcludedCategories | （空） | 不改堆叠上限的类别 ID，逗号分隔 |
| RestoreLosses | （空） | 损失补偿："配置ID:目标总数"（如 20001:18），补足后请清空 |
| DebugLogging | true | 诊断日志，玩稳定后可改 false 减少日志 |

## 合并 / 拆分的保护规则

- **多次使用的物品不合并、不堆叠**（官方烹饪按单份处理，见上）
- **使用次数非满不合并**：同类堆必须都是满次数才能合并（避免"3 次的和 2 次的合并算几次"）
- **个体属性内容不同不合并**：完美品质料理和普通料理各自独立；
  属性完全相同的同类可以正常合并
- **保质期取较长**：可堆叠的保鲜物品合并后，保留更新鲜那个的保质期
- **拆分**：带个体属性数据的物品不支持拆分（防止属性共享错乱）；
  目标容器放不下新堆则不拆，物品绝不会丢失

## 常见问题

**Q：点了整理为什么不是瞬间合并？**
A：合并发生在整理按钮按下约 0.3 秒后（避开游戏整理流程的防冻结设计），正常应无感知；
若界面偶尔没刷过来，约 3 秒内会自动补一次同步。

**Q：为什么野兔/大米这类食物不能堆叠了？**
A：官方烹饪管线按"1 份 = 1 个实例"设计（预拆分机制要求堆叠上限为 1），
堆叠它们会导致烹饪时整份被一次性消耗。这是游戏机制限制，不是 bug；
单次使用的食物和普通物资不受影响。

**Q：书读了几次后显示 u1/3 是 mod 弄坏的吗？**
A：不是。使用次数是游戏本体的消耗机制（每读一次 -1），mod 的拆分/合并会原样保留它。
