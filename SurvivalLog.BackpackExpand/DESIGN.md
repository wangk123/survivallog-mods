# 背包扩容 BackpackExpand — 设计文档

> 本文档随源码存放在 mod 自己的文件夹内；**每次迭代改动必须同步更新本文档**（文档维护规则见 `docs\00-目录说明.md`）。
> 版本：跟随套件 version.json；版本号由作者定义。
> **2026-10-25 数值化改版（作者定稿）**：倍率制（宽高 ×1.5 / 负重 ×2）→ **全局三数值键**（配置面极简，6 键封顶）；天赋"背包加一行"照常生效。原生值验证于 gamekb `2026-10-23_26157732`。

## 1. 功能定位

把可穿戴背包的格子容量和负重上限按**明确数值**调整（不再用倍率）：`[Expand]` 节三个数值键统一应用到全部 9 个可穿背包，任一键改 `0` = 该维度恢复官方原值。不改存档、不改游戏文件，删 dll 即还原。

## 2. 实现原理（原生机制实证，反汇编 + 运行时 dump）

- 改写对象是**内存配置表** `ConfigManager._Config_Bag_Dict`（键 = BagId）。
  `Config_Bag.Size` 为 `List<int>`，`[0]=宽 [1]=高`；游戏逻辑层、天赋层、UI reducer **三层实时直读该表，无快照**——改完立刻反映到背包界面。
- `Config_Bag.Burden`（负重）不同：它是 `BagComponent.OnInit / SetBagConfigId` 时的**快照**，改表后需要**重新读档**才体现到玩家身上。负重上限公式（GetMaxBurden 反汇编实证）：`Round((Burden + ExtraBurden) × (1 + 天赋比例) + 天赋固定值)`——mod 改的基础值与天赋加成独立叠加，天赋收益不被吞。**负重无 0=无限制语义**，mod 永不写 0 进表（0=恢复原生）。
- 改完 Size 后把 `ConfigManager._bagSizeSet` 置 null（尺寸白名单懒重建，见共享源码）。

### 名单与天赋链（2026-10-25 全量查证）

- 名单 `{1,2,5,6,7,8,9,10,11}` = **全部可穿背包**：
  - **初始包按角色分**（`Config_Player.Bag` 实证）：打工仔/大学生/退伍军人开局 **1 普通背包（8x7）**，仓库管理员开局 **8 仓管背包（9x8）**；
  - **天赋加行三连**（31931 外挂网兜 / 31932 侧袋改造 / 31933 背负扩展架，描述"背包可用格子增加一行"）：`BagGridBagIdsByInitialBag` 按初始包分派升级目标——初始 1 的换 5→6→7，初始 8 的换 9→10→11，每级"同宽 +1 行"；
  - **2 野外登山包**（10x8）非任何角色初始、不在物品表（背包是装备体系非物品），中途获得，无升级链；
  - 购物车 3 / 轿车 4 刻意不含（容量巨大无需扩）。
- **数值制与天赋的配合**：`Height` 键语义=**基础高度**——初始包/登山包目标高 = Height，天赋链上第 N 级 = Height + N（mod 内置链级数表，复刻原生加行结构）→ 天赋描述继续成立、换包逻辑（新包尺寸 ≥ 当前包）天然满足。`Width` 全包统一、`Burden` 全包统一（原生分档差异被统一值抹平，作者定稿接受）。
- **幂等与原生值缓存**：会话首见即原生（NativeW/H/B 三字典分字段独立缓存——首条扫描时 Size/Burden 可能单边读取失败）。5 秒轮询防读档/切场景表重载覆盖（旧 mod 验证过的模式）；配置改动 SettingChanged → 立即重算。

## 4. 配置项（BepInEx\config\com.local.survivallog.backpackexpand.cfg，共 6 键）

| 节.键 | 默认 | 说明 |
|---|---|---|
| General.Enabled | true | 总开关（ModCenter 启停位）：false=全部回写官方原值并停写；下次启动不加载（零日志零改写） |
| Expand.Width | 11 | 背包宽度（全部背包统一列数）。0=恢复官方原值 |
| Expand.Height | 10 | 基础高度：初始包与登山包的行数；天赋『背包加一行』每级自动 +1（照常生效）。0=恢复官方原值 |
| Expand.Burden | 48000 | 负重上限（全部统一基础值，天赋加成照常叠加）。0=恢复官方原值。**改后需读档** |
| Global.MaxWidth | 16 | 宽度上限（Width 超出即夹；0=不封顶自担）。背包页双栏布局过宽挤压右侧；16=防呆值（原生最大宽 10、作者实测 14 正常） |
| Global.MaxHeight | 18 | 高度上限（Height+天赋行数超出即夹；0=不封顶）。18=防呆值 |

默认值 = 作者 2026-10-25 本机口径的整数等价（宽高 ×1.4、负重 ×5，基准普通链头原生 8x7/9600）。原生值双源定案：10-23 表快照反推（快照时宽高 ×1.5、负重 ×5，9 条 AwayFromZero 全吻合）+ 旧版 DESIGN §5 记载（负重 9600/12000/12480 吻合）。

生效口径：全部键 SettingChanged 即时（宽高当帧体现；负重读档体现）。

### 旧倍率 cfg 迁移（一次性）

首跑检测旧 `[Expand]` WidthMult/HeightMult/BurdenMult（缺键按旧默认 1.5/1.5/2）→ 按普通链头原生基准换算（AwayFromZero、倍数下限 1）赋给新三键并 `Config.Save()` 立即落盘（防下次启动迁移不触发回默认）→ `[Expand]` 节整段重置（旧键与旧名单键 ExtraIds/ExcludeIds 全清）、试点期 `[Bag.*]` 节整段删。作者本机 1.4/1.4/5 换算值恰等于默认 11/10/48000（体验零变化）。

### General.Enabled 启停门

- Bind 最前；`Load()` 全部 Bind 完成后 `if (!Enabled.Value) return`——不创建 Ticker、零日志（表值本会话从未改过；迁移是纯文件维护仍执行）。
- Ticker 轮询体首行 gate：false 时若本会话已落笔（Engine.Applied），把进过原生缓存的全部包回写原生值，完成后停写。
- 边界：负重是读档快照，运行中关闭只还原表值，已穿背包的负重需读一次档才回官方值。

## 6. 与原生 / 其他 mod 的交互

- 天赋（加行换包链、负重比例/固定加成）：全部照常（链级数表保递增 + 负重公式独立叠加）。
- 与 CabinetSize / FridgeChill / CabinetBurden 名单互不重叠，可任意组合安装；共享层零改动。
- ModCenter：面板暴露 5 键（扩容数值 3 + 防呆上限 2），Enabled 走侧栏启停位（Meta 对账见其 DESIGN 2026-10-25 条目）。
- 不写任何存档字段、不碰 Data_Item；卸载后配置表随进程回收，游戏回到原版。

## 7. 已知限制

- 负重改表后需重新读档（快照机制，无法绕过）；老存档已穿背包：格子立即变（直读），负重要读一次档。
- 统一值抹平原生宽度/负重分档（登山包原 10 宽/仓管负重优势不再体现）——极简配置的固有取舍，作者定稿。
- MaxWidth/MaxHeight 默认 16/18 是防呆值非 UI 出屏实证预算；MaxHeight 若配得 ≤ Height+3 会把天赋行夹平（合法但天赋加行无感），玩家自担。
- 玩家把 Height 配大后点天赋：链上包全部变高（含已换的），行为与原生一致。

## 9. 迭代维护清单（改本 mod 时同步更新）

- 调默认值 → §4 默认列 + `Load()` Bind 默认值 + make_mods_release 归一目标同步改；
- 改名单/上限/新增配置 → §4 §5；
- 改实现方式（轮询节奏、改写通道、迁移逻辑）→ §2 §3 并注明依据；
- 发现新的原生交互/限制 → 补 §6 §7；
- 挂钩点（Config_Bag.Size/Burden 改写）不变时 moddeps.json 无需动；
- 每次发版在根 CHANGELOG.md 补一节（publish.ps1 强制校验）。
- 版本与发版（2026-10-28 起）：版本号单源 = 根 `version.json` 的 `mods.BackpackExpand` 字段（作者定义）；单 mod 发版走 `tools\release_mod.ps1 -Mod BackpackExpand`；本 mod 的 GitHub 镜像仓由 `tools\sync_repos.ps1` 从 HEAD 快照同步（详见 docs\superpowers\specs\2026-10-28-repo-split-and-online-update-design.md）。
