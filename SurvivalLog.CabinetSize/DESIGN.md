# 柜子容量 CabinetSize — 设计文档

> 本文档随源码存放在 mod 自己的文件夹内；**每次迭代改动必须同步更新本文档**（文档维护规则见 `docs\00-目录说明.md`）。
> 版本：跟随套件 version.json（版本号由作者定义）。
> 定稿：2026-10-24（三轮拍板，见 §10）；**取代 `SurvivalLog.CabinetExpand`**（退役留档，见 §8）。

## 1. 功能定位

**数值型**调整家里的柜子容量：全部"家里的柜子"按 小/中/大/特大 四档统一调到固定宽×高（**PresetV2，作者 2026-10-25 实测定稿：小 14x10 / 中 16x12 / 大 18x14 / 特大 20x16**），不再用百分比倍数。

- **12 个常用包**在 cfg 预生成显式宽高条目（置物架家族 5 + 冰箱 4 + 载具 3），独立可调；
- **其余家里的柜子**自动按档位规则生效（cfg 不列出条目），玩家想单独改某柜时手动加 `[Bag.<id>]` 节覆盖——**这是两组柜子的唯一区别**（用户拍板 2026-10-24）；
- **全局上限**（默认 20x16）：任何条目（默认或自定义）超出即夹到上限，确保不超出屏幕、不变形；
- **弃用自研视口适配**（ViewportFit 全部代码不迁移），完全采用游戏官方原生自适应；
- 不改存档、不碰物品；卸载即还原（超界物品由 SetBagPosSafe 坐标矫正挪回，旧 mod 已验证机制）。

宽度上限 20 的实证依据：官方 `createViewportFit` 有欠缩盲区（flex 挤压→测量看不见顶出的右栏），**实测触发于 23 列**（烹饪页右栏出屏 28px，CabinetExpand DESIGN §3.1）；Player.log 全表扫描实证**原生全表最大宽度=20（材料架）**，官方 UI 设计预算即 20 列（§3.2）。高度默认 16：超出原生最大高 12，系作者 2026-10-25 实机实测接受的高度口径（宽度仍守 20 预算）。

## 2. 实现原理

继承 CabinetExpand 的已验证机制（改写层 / 轮询 / 发现），替换其值解析模型：

- **改写层**（复用 `ModShared\BagTableRw.cs`）：改 `ConfigManager._Config_Bag_Dict[id].Size` + `_bagSizeSet` 置 null 重建白名单。
- **值解析优先级**：cfg `[Bag.<id>]` 显式值（`0` = 恢复该包原生）＞ 档位规则（按**原生格数**分档，见 §5）＞ 夹全局上限（MaxWidth/MaxHeight，`0` = 不封顶）。
- **受管集发现**（沿用，略去冷链分组）：
  - 家具自动发现：扫 `Config_Furniture` 全部 `BagId>0`（不限 FurnitureType，实测不可靠）；
  - 黑名单 34 包剔除（机器槽/纸箱共包/门窗口暂存/无人机/载具场景柜/纯场景搜刮，口径=CabinetExpand DESIGN §5 2026-10-13 拍板，名单见 §5.3）；cfg `ExcludeIds` 追加排除；
  - 载具：枚举 `Config_Vehicle` 全部 `TrunkBagId`（车表随对局加载，就绪首轮补录）+ 门口塑料袋专用包 **1023** 常量种子（与 SUV 后备箱共用）。
- **幂等与原生值缓存**：档位规则需要原生格数分档，沿用"会话首见即原生"缓存（NativeW/NativeH）；目标值会话缓存（bagId→目标宽高），配置变更（SettingChanged / 文件重解析）清缓存重算。5 秒轮询防读档/切场景表重载覆盖。
- **热生效双通道**：
  - BepInEx 绑定键（`[全局]`/`[档位]`/诊断键）：SettingChanged → 立即重算；
  - `[Bag.*]` 节：mod 自监听 cfg 文件（每轮 mtime stat，变更即重解析自己的节）——玩家/作者用记事本改条目、加新包**即时生效无需重启**。BepInEx 对未知节按 orphan 原样保留回写，两套读写互不干扰；12 包默认条目由 mod 首跑时写入文件（实现注意：与 BepInEx Save 的并发以"只在检测到文件缺节时追加一次"收窄）。
- **双开防御**：启动时检测 `com.local.survivallog.cabinetexpand` 在 `Chainloader.PluginInfos` → 日志警告并自禁（两 mod 同写 `Config_Bag.Size` 是旧拆名单根因，必须挡）。
- **诊断**（继承）：`BagComponent.OnInit` postfix（DiagOnOpen 门控，读档列全部容器 BagConfigId，排查"某柜不生效"）；ListOnReady 首轮自证，载具表就绪轮再重写一次全量 trace（"已是"快照，耐久证据含车表 1021/1022——首轮快照时车表未就绪会缺这两行）；受管载具包实例初始化打点（门口袋落地自证）。

## 4. 配置项（com.local.survivallog.cabinetsize.cfg）

| 节.键 | 默认 | 说明 |
|---|---|---|
| 全局.MaxWidth | 20 | 全局宽度上限（倍数/档位/自定义都夹；0=不封顶，自担风险） |
| 全局.MaxHeight | 16 | 全局高度上限（同上；作者实测口径） |
| 全局.Preset | 2 | 预设版本号：升级时玩家未动过的条目自动跟新默认（对策 cfg 首跑固化坑） |
| 档位.小.Width / Height | 14 / 10 | 小档阶梯值（改一档=全部未列出的小档柜生效，含未来新柜） |
| 档位.中.Width / Height | 16 / 12 | 中档 |
| 档位.大.Width / Height | 18 / 14 | 大档 |
| 档位.特大.Width / Height | 20 / 16 | 特大档 |
| Bag.<id>.Width / Height | 见 §5.1 | **12 包预生成显式值**；`0` = 恢复原生；玩家自加节同格式即时生效 |
| 诊断.ListOnReady | true | 首轮日志列全部受管包与前后值 |
| 诊断.DiagOnOpen | false | 读档列全部容器 BagConfigId |
| 全局.ExcludeIds | 空 | 追加排除 BagId（受管集两组都排） |

注意：ModCenter 的 cfg 反射桥只覆盖 BepInEx 绑定键（全局/档位/诊断）；`[Bag.*]` 走文件监听不在桥内（ModCenter 后续可扩展）。

## 6. 与原生 / 其他 mod 的交互

- **单写者原则延续**：CabinetExpand 退役后本 mod 是全游戏唯一写家具包 `Config_Bag.Size`；BackpackExpand 只管背包链 1-11（天然不相交）；FridgeChill 只改 `Config_Furniture.ColdRate`，零冲突（其静态名单不变）。
- **ViewportFit 移除的边界**：默认与档位值全部 ≤20x16（宽 20=官方预算内；高 16=作者实测口径）；官方零适配三页（酿酒桶/染色台/老鼠笼）回归纯官方行为（官方锁先小后大节奏），列入 §7 验证矩阵。
- **ModCenter**：mod 清单条目由 CabinetExpand 改为本 mod；cfg 桥覆盖 BepInEx 键（§4 注意）；将来"柜子负重并入柜子系 mod"的规划指向本 mod（结构预留：Size/Burden 同表，本次不实施）。

## 7. 实测验证矩阵（交付门槛；UI 改动先实机再报"修好"）

1. **四档宽度 × 主要界面**：14/16/18/20 宽柜子分别打开 背包双栏 / 烹饪 / 制造台 / 材料架对接页（制造台/粉碎机/交易/无人机），确认右栏不出屏、无变形；
2. **官方零适配三页**（弃守卫后）：对接 16/18/20 宽柜看是否溢出——红灯则相应档宽降到 16 重测；
3. **门口塑料袋**：1023 改 18x14 后装袋/卸货正常（TryMoveBagAll 溢出留后备箱语义不变）；
4. **存量存档兼容**：旧档超界物品 SetBagPosSafe 矫正复测一次；
5. **双开防御**：旧 dll 在场时新 mod 自禁且日志可见；
6. **热生效**：改档位/改 12 包条目/自加新包节，均不重启 5 秒内落地。

## 9. 已知限制

- **迷你柜跃进大**：小衣柜 110006 原生 15 格→小档 140 格（×9），"小柜统一到小档"的固有语义；作者实测若嫌跳变可加"迷你档"（已留档位表结构，加一行键即可）；
- **12 包显式值与档位值漂移**：改 `[档位.小]` 不会同步已列出的 12 包（它们是独立数值）；README 写明"改档位=改全部未列出柜 + 未来新柜"；
- 特大档 20x16 高度超出原生最大高 12（作者实测口径）；若未来玩家反馈高柜界面不适，可经 cfg 全局 MaxHeight 下调；
- 黑名单成员（纸箱/机器槽/场景柜）保持原值不变，加回走玩家自加 `[Bag.<id>]`（注意 1010/2003 等共包的连带影响自担）。
