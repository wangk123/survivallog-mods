# 生存日志 MOD 套件（SurvivalLog Mods）

《生存日志》(Survival Log, Steam AppID 4164790) 的 BepInEx 6 (IL2CPP) 插件套件。
单 DLL 部署、不改存档、不改游戏文件，卸载即还原原版。

## MOD 一览

| MOD | 功能 | 备注 |
|---|---|---|
| 基座 Base | BepInEx 6 框架 + .NET 运行时 | 必装，任何 MOD 依赖它 |
| 背包扩容 BackpackExpand | 背包格子宽、高各 ×1.5（约 2.2 倍面积），负重 ×2 | 仓管背包/登山包全覆盖，天赋加成照常叠加 |
| 柜子容量 CabinetSize | 家里全部柜子按小/中/大/特大四档统一调到固定宽×高（默认 14x10~20x16），13 个常用包独立微调，任意柜可个性化定值 | 数值型，取代旧「柜子扩容」；上限 20x16 防出屏；改值热生效 |
| 冰箱保鲜 FridgeChill | 保鲜 5 倍 → 10 倍 | 旧食物移出再放回一次即按新系数重算 |
| 动作提速 QuickAction | 搜查/撬锁/修理/看书等 77 项动作逐项可调，默认 0.5 秒 | 吃东西类只缩短不延长；配置全中文注释 |
| 储藏柜直达 CabinetEverywhere | 储物柜/橱柜/金属柜进工作台、无人机交易、烹饪（含老鼠笼/酿酒桶/颜料桶）等界面容器页签；按界面场景视图（食物/材料）自动收窄页签，或下拉按标签筛选 | 制作自动取料走官方"制作材料源"白名单；原独立 mod"柜子标签筛选"已并入（2026-10-17），名单/视图/筛选均可配置 |
| 柜子负重解放 CabinetBurden | 全部带负重上限的储物家具（10 种）负重无限制，格子没满就能继续放 | 负重清零=官方无上限语义，负重条自动隐藏；默认排除购物车/轿车（可调） |
| 角色专属解锁 RoleUnlock | 藤蔓种子全角色可发现（含种植/护盾）；燃烧瓶等防御配方四角色互通 | 纯表编辑；防御等级门槛照旧（可配置）；关配置自动还原 |
| 机器人提速 RobotSpeed | 修理/整理/种植机器人动作对齐手速，移速/充电/续航翻倍，三台货舱扩容 | 每项倍率可改；不含插槽与模块 |
| MOD 管理中心 ModCenter | 主菜单/游戏内 ESC 加「MOD 管理」入口，面板集中开关、调参全套件 mod，第三方 mod 通用页 | 管理器不改玩法；滑条改完几秒生效 |
| 无尽守卫 EndlessGuard（囤鼠桃园） | 无尽模式永不沦陷+已沦陷点读档恢复+倒计时清空；11 条后期拾遗规划（D100 起）防资源枯竭 | 存档只走游戏自己的接口；与自选规划兼容 |
| 自选规划 PlanPick | 生存规划三选一页加「自选规划」入口，全部规划可搜可买 | 非今日候选默认两倍价（100~300 可调）；今日候选原价 |
| 灾前加速 PreDisasterSpeed | 官方灾后五键倍速条搬到灾前，按钮+快捷键变速 | 走游戏自带换档通道；各档速度语义与官方一致（三键=×32 快进档） |

数值都可以在 `BepInEx\config\` 下的配置文件里调整。

> 各 mod 独立仓库与更新包：**https://github.com/survivallog-mods**（组织主页有全部链接）。

> `SurvivalLog.StackLimit999`（堆叠 999）为历史项目，**有未修复缺陷，不参与任何发布**，源码仅存档。

## 安装（玩家）

- **完整安装**（新玩家推荐，含 BepInEx 基座）：安装包只在**百度网盘**分享（链接由作者在分享渠道发布）。
- **单 mod 更新**：12 个 mod 在 GitHub 组织 [survivallog-mods](https://github.com/survivallog-mods) 各有独立仓库，Release 页提供最新版单 mod 安装包（`SurvivalLog.<Mod>_v<版本>.zip`，附 `update.json` 版本契约）；游戏内「MOD 管理中心」后续支持一键在线更新。
推荐使用一键安装器 `生存日志MOD安装器_v<版本>.exe`：自动探测 Steam 游戏目录、
自选 MOD 组件、玩家已有配置不覆盖、自带卸载器；也可以下载各 MOD 的独立 zip 手动安装。
详见发布包内《【必读】安装说明.txt》。

## 版本管理机制（开发者）

- **`version.json`** —— 全套件唯一版本号（`suite` 字段）。**版本号只由作者本人定义**，
  版本号自 v1.0.0 起正式管理；所有打包脚本、安装器、安装说明、插件内部版本常量都从这里读取，
  别处不允许出现硬编码版本号。
- **`CHANGELOG.md`** —— 每版更新说明。发版脚本强制校验：没有对应版本的小节就拒绝发版。
- **`tools/publish.ps1`** —— 一键发版流水线：校验版本与说明 → 同步插件版本常量 →
  构建 → 打 zip 包 → 编译安装器 → 生成安装说明 → 静默安装/卸载回归测试 →
  组装网盘上传目录 → git 提交打 tag → 创建 GitHub Release（仅更新说明）。
  **GitHub 只做源码管理，Release 不附安装包；安装包仅同步百度网盘。**
- 发版流程：改代码 → 作者定版本号（改 `version.json` 或口头指定）→ 在 `CHANGELOG.md`
  补该版说明 → 跑 `tools/publish.ps1` → 上传 `release\baidu_upload\` 到网盘。
- 完整机制说明见 [docs/05-版本管理与发版.md](docs/05-版本管理与发版.md)。

## 仓库结构

| 位置 | 内容 |
|---|---|
| `SurvivalLog.*/` | 各 MOD 源码工程（`dotnet build -c Release`）；**每个 mod 文件夹内有 `DESIGN.md` 设计文档，迭代时同步更新** |
| `ModShared/` | 多 MOD 共享源码（表直写工具，见其 `README.md`） |
| `installer/` | Inno Setup 安装器脚本（版本号由编译参数注入） |
| `tools/` | 构建/发版/回归脚本与逆向研究脚本 |
| `docs/` | 项目文档：需求、技术设计、教训红线、版本历史 |
| `version.json` / `CHANGELOG.md` | 版本单源 / 更新说明 |
| `release/`（不入库） | 发布产物：zip 分包、安装器、安装说明 |
