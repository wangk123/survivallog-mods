# 需求文档 — 生存日志堆叠 Mod（SurvivalLog.StackLimit999）

> 游戏：《生存日志》(Survival Log) Steam AppID 4164790
> 类型：BepInEx 6 (IL2CPP) 单 DLL 插件，不改任何游戏文件

## 核心需求（用户原始诉求）

1. **物品堆叠上限 999**（原版所有物品 StackLimit=1，一格一件）
   - 可配置，支持排除类别/物品
2. **负重上限按倍数**（默认 100 倍；内部单位克）
   - 早期固定值方案已废弃（99999 在新版游戏触发寻路 bug）
3. **合并**
   - 拖拽合并：同类物品拖到一起自动合并
   - 一键整理合并：背包/容器整理时先合并再排序
4. **手动拆分**
   - 最终形态：**Shift+左键** 点击物品堆，拆出 SplitCount 件（默认 1）
   - 生效范围：背包、柜子、**工作台制作页**（此前必须关工作台再开柜子才能拆）
   - 右键保留原版快速转移；Alt=游戏详情、Ctrl=游戏拾取，均不可占用
   - 历史方案：R 键（Unity Input 收不到部分键盘）→ Alt+左键（被游戏详情占用）→ 双击（用户不便）→ Shift+左键（替代原版转移，右键转移保留）✅
5. **安全性红线（血泪教训，见 lessons-learned.md）**
   - 绝不修改游戏文件；单 DLL 可删除即完全卸载
   - 绝不克隆物品对象（原生管线崩溃）
   - 绝不置零活物品后依赖恢复（物品丢失）
   - 绝不改反应层（Redux）校验结果（无限重渲染卡死）
   - 绝不用第三方容器做中转（虚拟容器污染 → 脏数据洪水 → 报错弹窗）
   - 合并后必须真正移除被并堆（不留 count=0 残骸写回存档）
6. **可配置**：BepInEx config 文件（中文注释），改文件即生效（重进游戏）

## 明确不做

- 不做工作台配方自动拆分/自动补料（v2.9.3-v2.9.4 试验：事件层重派发方案有物品复制副作用，已回滚；用户接受手动拆分流程）
- 不做任何存档数据清洗/修复（用户明确要求删除；清理逻辑一律不做）
- 不做调试热键（F7 等已全部删除）

## 工作台多材料配方的使用方式（已知限制，非 bug）

游戏按「件数」计数材料（1 格 = 1 件），堆叠后的材料在配方里只算 1 件。
用户操作：Shift+左键拆出所需件数的单件 → 右键/拖入工作台材料格 → 制作。
