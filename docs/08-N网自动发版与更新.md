## 0. 机制事实（2026-10-24 核实，勿凭旧印象）

来源：官方公告 news/15454（2026-03-17 Upload API Open Beta）、v3 OpenAPI 规范（`https://api.nexusmods.com/v3`，46 端点）、官方 GitHub Action `Nexus-Mods/upload-to-nexus-mods` v1.0.0-beta.11。

- Upload API 官方定位：**程序化更新已有 mod 页**（给已存在的文件挂新版本）。
- v3 上传链路：`POST /uploads`（建会话）→ `POST /uploads/multipart`（分块传）→ `POST /uploads/{id}/finalise`（完成，直传云端 + 自动接病毒扫描）→ `POST /mod-files/{id}/versions`（挂新版本）。
- 辅助端点：`POST /mods/{id}/changelogs`（更新日志）、`PATCH /mods/{id}`（改描述）、`POST /mod-file-versions/move*`（文件重组）。
- 认证：**个人 API key**（免费作者账号即可；mod 页团队成员的个人 key 也行）。
- **不能创建新 mod 页**（官方确认在路线图上）：每个 mod 的**首版**仍需网页手动建页 + 传第一个文件，之后每次更新可全自动。
- 已知 beta 坑：上传后文件名偶发 `.zip.zip` 双后缀；无独立"归档旧版"端点（Action 的 `archive_existing_version` 参数除外）；beta 端点变更走 90 天弃用期。
- 玩家侧更新是**拉模式**：Vortex / Nexus Mods App 轮询 API 比对文件 version 字段提示更新；网页手动下载的玩家不会自动收到更新。
- **图片限制**（官方 Mod Page Guide）：单图 **≤400KB**，超限转 JPG；展示图建议 16:9；缩略图由站方自动生成（主体居中、留安全边）。

## 1. 红线（本通道专属，叠加在 AGENTS.md 通用硬规则之上）

1. **API key 永不入库**：本地单源 `tools/secrets/nexus_api_key.txt`（`.gitignore` 已锚定 `tools/secrets/`，2026-10-24 `git check-ignore` 实证命中）。若走 GitHub Action 方案，另允许存一份进 GitHub Secrets（平台加密，标准做法）。任何脚本 / 日志 / 截图不得回显完整 key。key 疑泄露时在 N网 Preferences 页 regenerate，换 key 只改文件不改代码。
2. **N网推送必须经作者确认**（作者 2026-10-24 指示）：publish.ps1 完成 GitHub Release 后**不得**自动推 N网；推送动作必须由作者显式触发 / 批准（确认门见 §4）。
3. 版本号单源不变：`version.json` 的 `suite` 字段（AGENTS.md 硬规则 1）。N网上传的 version 字段一律取自 tag / version.json，助手不得自定。
4. 禁发名单不变：StackLimit999（硬规则 6）、探针类（硬规则 5）绝不进 N网上传名单。
5. 遵守 N网 API Acceptable Use Policy（频率限制）。
6. **图片合规**：上传图 ≤400KB/张（超限转 JPG 重渲）；封面出图后必须渲染自检 + 作者过目才上传；封面素材红线（禁纯抽象图形 / 禁假界面）见 §5.1。

## 3. 每次发版的完整流程

```
作者定号（version.json）                          ← 硬规则 1，一切起点
   ↓
CHANGELOG 补该版小节（可由助手代写）
   ↓
publish.ps1（校验→构建→打包→安装器→回归→tag→GitHub Release）   ← 现有流水线，docs/05
   ↓
百度云安装器渠道照旧（人工上传网盘）
   ↓
【确认门】作者显式触发 N网推送（§4）
   ↓
N网推送执行（脚本 / Action）：
   1. 读 tag/version.json 定版本号 + nexus_ids.json 定目标 mod
   2. 取 publish.ps1 产出的 zip（§6 包结构，渠道不拆包）
   3. v3 上传链：uploads 会话 → multipart → finalise → 挂新版本（version=定号）
   4. POST changelogs（从 CHANGELOG.md 对应小节自动提取）
   5. PATCH /mods/{id} 刷新描述（README 改版时；文案单源=README，§5.2）
   6. （可选）archive_existing_version 归档旧版
   7. 自证回读：GET /mod-files/{id}/versions 核对最新 version 字段 == 定号
   ↓
（可选）抖音 / 群通告
```

封面图不随每次发版更换：仅**首版建页**与**重大改版**时出新图；页脚版本号如需更新属"重大改版"口径。

## 4. 确认门设计（"发版必须经过作者确认"的落地）

推荐 **GitHub Actions `workflow_dispatch` 手动触发**：

- **触发即确认**：作者在仓库 Actions 页点 "Run workflow"，选 tag、勾 mod 范围——这一下就是确认，天然留痕（谁、何时、传的什么）。
- **不做** `release: published` 自动触发——那等于自动发版，违反红线 2。
- workflow 输入建议：`tag`（默认最新 release）、`mods`（默认常表全量）、`dry_run`（只打印不传，**首跑必开**）。
- 官方 Action 关键入参对照：`api_key` / `file_id` / `filename` / `version` / `display_name` / `description` / `category`（默认 main）/ `changelog`（需带 `mod_id`）/ `archive_existing_version`。
- 备选：GitHub Environment + required reviewer（release 后自动建 run、作者点批准）——同样满足确认门，配置略多。本地脚本 `-Confirm` 交互式作为无 GitHub 环境的兜底。

**确认时作者过目四项：版本号、mod 清单、changelog、是否归档旧版。**

**素材红线（三条，违反即重做）**：

1. **必须真实游戏素材**：底图 = Steam 官方实机截图（存 `gamekb/steam_shots/`，gitignored）；点缀图标 = 游戏 WebUI `Res/` 真物品图标。**禁纯 CSS 抽象图形**替代游戏画面。

## 7. 玩家侧更新的预期（对作者）

- Vortex / Nexus Mods App 用户：管理器内自动检测到新版本，一键更新。
- 网页手动下载玩家：不会自动收到更新，需回 mod 页重新下载（页面显示新版本号 + changelog）。
- 国内百度云安装器渠道：不受影响，照旧。

## 8. 故障与兜底

- 上传中断 / 失败：upload 会话可放弃重开；兜底 = 网页手动上传（表单常开）。
- beta 端点变更：推送脚本头部先 `GET openapi.yaml` 核对端点仍在，缺失即中止并提示（90 天弃用期，低频风险）。
- `.zip.zip` 双后缀：推送成功后网页过目文件名，必要时网页改名。
- 传错版本：beta 阶段无 API 删除文件，需网页处理——所以 dry_run 首跑 + 确认门四项过目是必须的。
- 图片超 400KB：JPG 重渲（§5.1）；描述文案传错：`PATCH /mods/{id}` 可改，兜底网页编辑。

**每个 mod 的建页步骤（作者网页操作，首版必须手动）**：

1. Nexus 建页：游戏 "Survival Log" → Upload a mod → 传封面 JPG（主图）。
2. Description 粘贴 `assets/nexus/pages/<Mod>.bbcode.txt` 全文（首行横幅占位 `PASTE_BANNER_URL_HERE`：先把封面/横幅传到本页图库再替换 URL；横幅 1300×372 如未制，可删掉首行）。
3. Files 上传双轨包（publish.ps1 产物）：主文件 `SurvivalLog-<EnName>-v<版本>-Full.zip`（category=main）+ 可选 `...-PluginOnly.zip`（勾 requirements popup 标注 BepInEx 依赖）。
4. 建页后回填 `tools/nexus_ids.json`（mod_id + 两个 file_id）——此后更新走 §3 自动流程。
5. Donation Points 建页时开启（可选，零成本）。
