# SurvivalLog.QuickAction — 动作提速 v2

## 功能
按游戏官方动作分类（Config_Action.ActionType）统一提速，每个分类一个开关（默认 0.5 秒走完进度条）：

| 分类 | 覆盖内容 | 可改条数（实测） |
|---|---|---|
| 物品使用 | 吃/喝/品尝/吞咽/享受/嚼/畅饮食物饮品、吃药/维生素（原 5~10 秒） | 约 2750 |
| 杂项交互 | 搜查/撬锁/开锁/翻找/查看/开关电器/拾取/洗手/上厕所/正在种植（原 0.5~30 秒） | 约 135 |
| 房屋维护 | 布置/安装/移动/拆除陷阱、安装家具、出门等（原 2.5~20 秒） | 约 78 |
| 家具功能 | 拆封包裹（约700）/种植/烹饪/升级大门/改装无人机/救援建造 | 约 900 |
| 娱乐锻炼 | 看书/阅读技能书/听音乐/按摩/运动/洗澡/打扫/空调吹风 | 约 173 |

游戏更新新增的动作自动归类覆盖——分类、周期结算守卫、引用判定全部运行时实时计算，无需更新 mod。

## 自动保护（v2 核心改进，全部运行时实证）
- **周期结算守卫**：部分动作的收益按"每 N 游戏秒结算一次"累积（总收益与耗时成正比），
  例如 修理设施/修补房门/加固房门/加固窗户（10 条）、生吃冷冻食品（32 条）、跳舞/掌上游戏机（5 条）、
  锻炼/持续发电/哑铃（3 条）、观察窗外/听收音机/冥想/写日记/瑜伽（Social 全部 5 条）——
  这些动作**永不改动**，提速不会削弱任何收益。
- **纯消耗型周期效果放行**（v2.1.1）：上厕所、翻箱倒柜、翻找书堆、整理杂志、清理障碍等
  交互动作挂的是周期性消耗（如上厕所每 15 秒饱食 -5）——提速反而省消耗，固定收益照拿。
- **睡觉/打盹不动**：其耗时兼任游戏时间推进（睡 3 小时=推 3 小时）。
- **内部行为不动**：情绪播报（"好饿！"）、呕吐/腹泻等强制状态、系统动作
  （判定依据：不被任何家具按钮或物品引用）。
- **只减不增**：原本快于目标值的动作（拾取 0.1 秒、吃药 0.2 秒等）不会被放慢。

## 原理（与同系列 mod 相同的内存改表模式）
- 动作耗时 = `Config_Action.During`（游戏秒）；探索/家场景时钟 1 真实秒 = 2 游戏分钟
  （TimeScale=120），1800 游戏秒 = 15 真实秒。本 mod 在内存中把 During 改为 `毫秒÷1000×120`。
- **不写存档、不改游戏文件、无 Harmony**；分类填 0 或删 dll = 恢复原值。
- 与天赋「眼明手快」（打开家具 -30%）方向一致、正常叠加。
- 副作用：动作消耗的游戏内时间同比例缩短，单个游戏日能做的事变多。

## 配置说明
配置文件 `BepInEx\config\com.local.survivallog.quickaction.cfg`（首次启动自动生成）；修改后即时生效，无需重启：

```ini
[分类修改]
## 吃/喝/品尝/吞咽/药品等入口动作（约 2750 条）。0=恢复原值。
# Setting type: Int32
物品使用Ms = 500
```

- 五个分类：物品使用Ms / 家具功能Ms / 房屋维护Ms / 杂项交互Ms / 娱乐锻炼Ms（v2.1 起统一默认 500；
  v2.0 旧配置会在升级后一次性把仍是旧默认 0 的家具功能/娱乐锻炼抬到 500，主动改回 0 不受影响）
- 单个动作微调：[其他] Overrides = `ID:毫秒` 逗号分隔（优先级最高，仅次于周期结算守卫；
  可命中分类漏掉的动作，如 上厕所 `9075:500`；`ID:0` 恢复原值）。
  完整名单看 `BepInEx\ActionList.txt`（ID|名称|类型|原耗时，删掉后下次启动重新生成）
- 睡觉（Rest）与社交（Social）两类无开关、绝不改动——睡觉耗时兼任游戏时间推进，社交全部为
  周期结算收益；防止误设置破坏游戏机制。
- 安装器勾选的分类作为初始默认值写入；已有配置键永远优先，重装不会覆盖调好的数值
- 动作之间的内置间隔（约 1.7 秒）与赶路移动速度不在范围内

## 安装
需先装好基座（见 SurvivalLog.Base 包）。把 `BepInEx\plugins\SurvivalLog.QuickAction.dll`
放进游戏 `BepInEx\plugins\`，启动游戏即生效（主菜单阶段已改写，无需进存档）。
验证：游戏启动后 `BepInEx\QuickActionTrace.txt` 记录本次各分类改写数与守卫跳过数。

## 卸载
删除 dll 即可；某类暂时不想改就把对应项设为 0。存档不受任何影响。
