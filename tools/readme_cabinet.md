# SurvivalLog.CabinetSize — 柜子容量（家里全部柜子 + 冰箱 + 载具后备箱）

## 功能
- 家里全部"柜子类"容器按原生大小分 **小 / 中 / 大 / 特大 四档**，直接改成固定格数（宽×高）——不是倍率，是想要几格就几格
- 覆盖：置物架全家族、柜子/金属柜/工具柜/衣柜/抽屉柜等全部家具柜、冰箱/冰柜、载具后备箱（自行车车筐 / 轿车 / SUV）与家门口塑料袋
- 12 个常用包在配置文件里有**独立条目**（首次启动自动写入），可单独微调
- 名单自动发现：**游戏更新新增柜子自动按档跟上**，无需改配置
- 改配置保存后几秒内自动生效，**无需重启游戏**（已打开的柜子界面重开即见）
- 与旧 mod"柜子扩容"（CabinetExpand）互斥：检测到双开本 mod 自动停用并在日志提示

## 安装
需先装好基座（见 SurvivalLog.Base 包）。把 `BepInEx\plugins\SurvivalLog.CabinetSize.dll` 放进游戏 `BepInEx\plugins\`，启动游戏即生效。
从旧版升级（装过 柜子扩容/CabinetExpand 或更早的冰箱扩容）：删除 `BepInEx\plugins\SurvivalLog.CabinetExpand.dll`（旧配置 `BepInEx\config\com.local.survivallog.cabinetexpand.cfg` 一并删掉更干净）。

## 四档与全局上限
档位按柜子的**原生格数（宽×高相乘）**划分：

| 档位 | 原生格数 | 默认改成 |
|---|---|---|
| 小 | ≤ 60 | 14 x 10 |
| 中 | 61 ~ 99 | 16 x 12 |
| 大 | 100 ~ 149 | 18 x 14 |
| 特大 | ≥ 150 | 20 x 16 |

全局上限 `[Global] MaxWidth / MaxHeight` 默认 **20 x 16**：宽度 20=官方 UI 设计预算（原生最大宽度=材料架 20 列），高度 16=作者实机实测口径；档位或自定义条目超出会被夹到上限。把上限调大（或 0=不封顶）后格子**可能挤出屏幕**，风险自担。
另有"不缩水"保护：算出的目标值比柜子原生还小时保持原生，不会把柜子改小。

## 12 常用包默认值（独立条目）
首次启动自动写入配置文件，可逐包单独改（这些是独立数值，改档位**不会**动它们）：

| 包 id | 容器 | 原生 | 本 mod 默认 |
|---|---|---|---|
| 110002 | 小型置物架 | 6x8 | 14x10 |
| 110001 | 中型置物架 | 8x10 | 16x12 |
| 110000 | 大型置物架 | 12x10 | 18x14 |
| 110008 | 超大型置物架 | 15x12 | 20x16 |
| 110009 | 材料架 | 20x12 | 20x16 |
| 1004 | 双门冰箱 | 8x7 | 16x12 |
| 115000 | 双开门冰箱 | 8x7 | 14x10 |
| 115001 | 冰柜 | 8x10 | 18x14 |
| 115005 | 大容量冰柜 | 12x10 | 20x16 |
| 1021 | 自行车车筐 | 5x4 | 14x10 |
| 1022 | 轿车后备箱 | 10x8 | 18x14 |
| 1023 | SUV 后备箱 / 门口塑料袋 | 12x10 | 20x16 |

材料架说明：它是"分行视图"（一行一种材料、按件数铺卡片），底层仍是格子——更高=能放更多种材料、更宽=每行放更多件。
mod 升级调整默认值时，没手动改过的条目会自动跟新默认（由 `Global.Preset` 管理，勿手改该键）。

## 配置
配置文件 `BepInEx\config\com.local.survivallog.cabinetsize.cfg`（被删则首次启动按默认自动重建）。修改保存后约 5 秒内自动生效。

| 节.键 | 默认 | 说明 |
|---|---|---|
| Global.MaxWidth / MaxHeight | 20 / 16 | 全局上限（0=不封顶，超宽可能挤出屏幕自担） |
| Global.Preset | 1 | 默认值预设版本（勿手改） |
| Global.ExcludeIds | 空 | 追加排除的 BagId（逗号分隔）：这些柜子恢复官方原值 |
| Tier.Small.Width / Height | 14 / 10 | 小档宽高（原生格数 ≤60 落此档） |
| Tier.Medium.Width / Height | 16 / 12 | 中档宽高（原生格数 61~99） |
| Tier.Large.Width / Height | 18 / 14 | 大档宽高（原生格数 100~149） |
| Tier.XLarge.Width / Height | 20 / 16 | 特大档宽高（原生格数 ≥150） |
| Debug.ListOnReady | true | 首次生效时在日志/trace 列出全部受管包与尺寸前后 |
| Debug.DiagOnOpen | false | 读档时在日志列出全部容器的 BagConfigId（排查用，平时关防刷屏） |
| [Bag.<id>] 节 | 见上表 | 单包独立宽高（见下节） |

数值优先级：`[Bag.<id>]` 独立条目 ＞ 档位 ＞ 不缩水守卫 ＞ 全局上限。

## 给其他柜子加条目
不在 12 包名单里的柜子按档位走；想单独定它的格数，在配置文件末尾照抄三行：

```
[Bag.1001]
Width = 14
Height = 12
```

保存即生效。把 Width 或 Height 改成 **0 = 该包恢复官方原值**（等价于排除它）。
注意 id 撞号：包 10002 是金属柜，家具"小型置物架"用的是包 110002——加错数字会改到别的柜子。

## 改档位还是改单包条目？
- **改档位**（`Tier.*.Width/Height`）：作用于所有"没有独立条目"的受管柜子，**包括未来游戏更新新增的柜子**——一处改，全体跟上。
- **改单包条目**（12 常用包 + 你自加的 `[Bag.*]`）：只影响该包，是独立数值，改档位不会覆盖它。
- 想让某几个柜子不受档位影响恢复原值，也可把包 id 填进 `Global.ExcludeIds`。

## 名单与排查
- 生效名单与每个包"原生 → 目标"对照：`Debug.ListOnReady=true`（默认开）时写入日志与自证文件 `BepInEx\CabinetSize_trace.txt`。
- 查某个容器用的包 id：开 `Debug.DiagOnOpen=true` 读档，看日志 `[CabinetSize][诊断] 容器初始化 bagConfigId=xxx（名字）` 行，把需要的数字写成 `[Bag.xxx]` 条目。
- 默认不碰（内置黑名单，功能容器非储物语义，无加回开关）：厨房电器槽位、老鼠笼/粉碎机/酿酒桶等功能机械、堆肥箱/吊篮（种植）、床/垃圾桶、纸箱、门窗口暂存、无人机、货车/手推车、纯场景搜刮容器。

## 卸载
删除 dll 即可还原；已放进扩容区域的物品会被游戏坐标矫正自动挪回，不会丢失。
