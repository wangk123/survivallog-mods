# 柜子扩容 CabinetExpand — 设计文档

> 本文档随源码存放在 mod 自己的文件夹内；**每次迭代改动必须同步更新本文档**（文档维护规则见 `docs\00-目录说明.md`）。
> 版本：跟随套件 version.json；机制与实证结论长期有效。

## 1. 功能定位

把**家里全部"柜子类"容器**（置物架全家族/柜子 1-3/金属柜系列/工具柜/床头柜/衣柜/玄关台/抽屉柜/材料架/储物柜等）**和冰箱族**的格子容量放大（默认宽、高各 ×1.5，柜子/冰箱两组倍数独立可调）。不改存档、不改游戏文件，删 dll 即还原。

用户拍板（2026-10-13）：**只扩家里的柜子，忽略其他**——机器槽（老鼠笼/粉碎机等）、纸箱共包、门窗口暂存、无人机、载具、纯场景搜刮容器全部默认排除（可 cfg 加回）。同日拍板：**原冰箱扩容 FridgeExpand 并入本 mod**（名字不变），冰箱族由"全冷链电器包"自动分组管理。

### 材料架（110009）实证：特殊视图，底层仍是格子

材料架面板右栏与制造台/粉碎机/交易/无人机中控台左栏共用**分行视图**（`webui-rackrows.js`，官方头注释实证）：一行=包里一个格子行，一行只放一种材料（名牌显示总件数），每行件数上限 cap=行长÷材料宽。即**高=能放几种材料（行数），宽=每行几件**——扩容语义清晰有效；行数据由 C# 从包格子实时构造，UI 动态适配，无固定行数上限。

## 2. 实现原理（原生机制实证）

与 BackpackExpand 同架构，差异在**目标名单机制**（详见 `ModShared\README.md` 与 BackpackExpand DESIGN §2）：

- 改写 `ConfigManager._Config_Bag_Dict` 内名单条目的 `Size`（三层实时直读）+ `_bagSizeSet` 置 null 重建白名单；
- 5 秒轮询幂等改写（防读档/切场景表重载覆盖）；
- 本 mod 不动 Burden（柜子负重由 CabinetBurden 管）。

### 名单 = 自动发现 + 黑名单（2026-10-13 统一化，同日并入冰箱扩容）

- **自动发现**：扫 `Config_Furniture` 全部 `BagId>0`（不限 FurnitureType——Type=0 里有大量原生家柜：床头柜 110003/衣柜 110004·110006/材料架 110009，实证 FurnitureType 不可靠）。
- **分组**：包的全部使用家具都是冷链电器（`IsElectrical && ElectricalType==1 && ColdRate>0`，与原生 CollectFridges 同判定）→ **冰箱组**（FridgeWidthMult/FridgeHeightMult 倍数，自动兜住未来新冰箱，如 2026-10-08 大容量冰柜 115005 那类）；其余 → **柜子组**。注意不能按"有任一冷链家具"分组——110001 与冰箱 66113 共包，但置物架/工具柜不是冷链，仍归柜子组。
- **黑名单 `DefaultExcludeIds`（34 包）**：见 §5，对两组都生效。
- 优先级：ExtraIds（cfg，按冷链属性加回对应组）> ExcludeIds（cfg，两组都排）> DefaultExcludeIds > 自动发现。
- 优点：**游戏更新新增柜子/冰箱自动跟上**，不再依赖手动补名单（原 FridgeExpand 静态名单漏大容量冰柜的事故类别根除）。

### 关键实证：家具名 ≠ Bag 表名（v1.3.0 定案，统一化的直接动因）

- 游戏内叫"工具柜"的家具 70006，实际用 **bag 110001**——与"中型置物架"**共用同一个包**；
- 置物架家族：小型=110002（另有 80032/80121 系"小型置物架"用 **bag 1001 柜子1**）、中型=110001、大型=110000、超大型=110008、材料架=110009；
- **v1.1.2 白名单（8 包）只有 110001 在置物架家族内 → 中型 8x10→12x15=180 格反超大型原生 12x10=120 格**——用户反馈"大型置物架反而比小型格子少"的根因；同理 1001（柜子1）没进名单而 1002/1003 进了。统一 ×1.5（AwayFromZero 取整对每维严格单调）恢复家族内大小排序。
- **id 撞号陷阱**：bag 10002=金属柜，家具 10002=小型置物架（用 bag 110002）——玩家自查加 id 极易加错，cfg/README 要写清。

## 3. 代码结构

| 文件 | 职责 |
|---|---|
| `CabinetExpandPlugin.cs` | 入口：配置定义、Rerun、`DiscoverTargets()` 名单发现（自动发现+冷链跳过+黑名单+cfg 套用）、挂诊断补丁、注入 Ticker |
| `BagInitDiag`（同文件） | Harmony postfix `BagComponent.OnInit(int)`：读档时列出全部容器实体的 BagConfigId/名称/当前尺寸（DiagOnOpen=true 时） |
| `CabinetTicker`（同文件） | 5 秒轮询幂等改写；ListOnReady=true 首轮在日志列出全部受管包与尺寸前后（自证+留档原生尺寸） |
| `ModShared\BagTableRw.cs` | 共享源码（编译进本 dll，本轮未改动——不触发 4 份扩容文档同步） |

### 诊断钩子的三代演进（都是实锤，复用前必读）

1. v1：patch `Ac_ToolTable_Open.SendAction`（泛型 List 参数）——挂载成功但**从不触发**（interop 泛型坑第二次实锤）；
2. v2：patch `Reducer_Web_ToolTable.Trigger_RA_Open`——同样不触发（根因：界面根本不走 ToolTable）；
3. v3（现行）：patch **实例方法** `BagComponent.OnInit`——实测可靠，读档即打印全部容器清单，一轮定位。
   结论：**patch 静态方法/带泛型参数的方法不可靠，实例方法可靠**（与旧 mod get_StackLimit getter 先例一致）。

## 4. 配置项（com.local.survivallog.cabinetexpand.cfg）

| 键 | 默认 | 说明 |
|---|---|---|
| WidthMult | 1.5 | 柜子宽度倍数（AwayFromZero 取整） |
| HeightMult | 1.5 | 柜子高度倍数（同上） |
| FridgeWidthMult | 1.5 | 冰箱宽度倍数；1=还原原生 |
| FridgeHeightMult | 1.5 | 冰箱高度倍数；1=还原原生 |
| ExtraIds | 空 | 追加 BagId（优先级最高；全冷链电器的包自动归冰箱组） |
| ExcludeIds | 空 | 追加排除 BagId（两组都排） |
| Verbose | false | 每轮输出明细 |
| ListOnReady | true | 首次生效时在日志列出全部受管包与尺寸前后（核对名单用） |
| DiagOnOpen | false | 读档时在日志列出全部容器的 BagConfigId（确认名单用，平时关防刷屏） |

cfg 兼容：老 CabinetExpand cfg 的 ExtraIds/ExcludeIds 键名与语义不变，直接沿用；新增键首次加载自动补默认值。原 FridgeExpand 的 cfg 变惰性文件（dll 已不存在，无害残留）。**cfg 首跑固化坑**：改代码默认值不会更新已生成的 cfg，发版说明需提示。

**天然不涉及**（自动发现的副产品优点）：玩家背包链 1-11（BackpackExpand 管）、购物车 3/轿车 4（装备体系）、工作台抽屉 5010/5012/5013（用户已明确撤销，且无家具引用）。

**某柜子不生效的标准排查法**：cfg 开 `DiagOnOpen=true` → 读档 → 看 LogOutput.log 里 `OnInit bagConfigId=xxx` 行 → 把该 id 加进 ExtraIds。

## 6. 与原生 / 其他 mod 的交互

- **单写者原则**：合并后全游戏只有本 mod 写家具包的 `Config_Bag.Size`（BackpackExpand 只管玩家背包链 1-11，与家具发现天然不相交）——旧"两 mod 共管一个包 ×1.5×1.5=×2.25 双乘"风险类别整体消除（BagTable 原值快照 OrigW/OrigH 是进程内字典，双写会互相污染原值，此为当初必须拆名单的根因）。
- FridgeChill 只改 `Config_Furniture.ColdRate`（保鲜倍数），与本 mod 的 Size 改写零冲突；其名单仍是静态 {1004,115000,115001,3002,115005}，未来新冰箱需手动补（独立事项）。
- 110001 与置物架/工具柜/大量场景家具（医疗器械台/货堆/药品柜等）共用包：扩 110001 全部共用者一起变大——共用包的固有属性，场景侧只影响搜刮容量，无害。
- 不写存档、不碰物品；卸载即还原（扩容区物品由 SetBagPosSafe 坐标矫正自动挪回）。

## 7. 已知限制

- 共用包无法只放大单一家具（110001 工具柜⇄中型置物架；1001 柜子1⇄场景贩卖机/轿车 90030 等）。
- 纸箱族（1010/2003）因与工具桌/载具共包被整体排除，家里放的纸箱不扩容（用户拍板；要加走 ExtraIds）。
- FridgeChill（保鲜）的 BagId 名单仍是静态 {1004,115000,115001,3002,115005}，未来新冰箱保鲜需手动补（与本 mod 的格子扩容互不影响）。

## 10. 防盗署名气泡（2026-10-14，套件统一）

- `Load()` 末尾调用 `SurvivalLog.ModShared.WelcomeTip.Install(Log)`（共享源 `ModShared/WelcomeTip.cs`，csproj 已链入）。
- 行为：进档后主角头顶显示 3 秒原生气泡文字——`AgentModel.Unit_ShowHeadTalk(text, 3)`（主角模型经 `WebGm.GetLeadingRoleModel(out string)` 获取）。实测主角头顶条为官方无框文字样式（silentHeadTalk 默认 false，ImmediateShowTalk/ShowTalk 直调同样无框，非本 mod 缺陷）；During≈真实秒（传 360 会远超 3 秒）。每次进档一次，回主菜单再进再弹。
- 7 个套件 mod 全部调用，靠 `GameObject.Find("SurvivalLog.WelcomeTip")` 去重：先到者创建 DontDestroyOnLoad ticker，其余跳过——装多个只弹一条。无 cfg 开关（防盗署名为内置行为，防剥离）。
