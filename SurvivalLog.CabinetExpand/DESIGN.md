# 柜子扩容 CabinetExpand — 设计文档

> 本文档随源码存放在 mod 自己的文件夹内；**每次迭代改动必须同步更新本文档**（文档维护规则见 `docs\00-目录说明.md`）。
> 版本：跟随套件 version.json；机制与实证结论长期有效。

## 1. 功能定位

把**家里全部"柜子类"容器**（置物架全家族/柜子 1-3/金属柜系列/工具柜/床头柜/衣柜/玄关台/抽屉柜/材料架/储物柜等）**和冰箱族**的格子容量放大（默认宽、高各 ×1.5，柜子/冰箱两组倍数独立可调）。不改存档、不改游戏文件，删 dll 即还原。

用户拍板（2026-10-13）：**只扩家里的柜子，忽略其他**——机器槽（老鼠笼/粉碎机等）、纸箱共包、门窗口暂存、无人机、载具、纯场景搜刮容器全部默认排除（可 cfg 加回）。同日拍板：**原冰箱扩容 FridgeExpand 并入本 mod**（名字不变），冰箱族由"全冷链电器包"自动分组管理。

用户拍板（2026-10-18）：**新增第三组"载具"**——车行三档后备箱（自行车/轿车/SUV）+ 家门口塑料袋（购物袋），宽高各 ×1.5（VehicleWidthMult/VehicleHeightMult 独立可调）。**购物袋数量上限（2 个）不扩**：`VehicleConfig.DoorBoxMaxCount=2` 深度固化（卸货循环内联 cmp 2 + 存档 schema 就是 DoorBoxItems/DoorBoxItems2 两个独立字段），加袋子数=存档格式改造，侵入度不成比例；扩格子（每袋装更多）已达成实际目的。溢出实证：到家卸货 `TryMoveBagAll` 能装多少装多少，装不下的留在后备箱不丢失。

### 材料架（110009）实证：特殊视图，底层仍是格子

材料架面板右栏与制造台/粉碎机/交易/无人机中控台左栏共用**分行视图**（`webui-rackrows.js`，官方头注释实证）：一行=包里一个格子行，一行只放一种材料（名牌显示总件数），每行件数上限 cap=行长÷材料宽。即**高=能放几种材料（行数），宽=每行几件**——扩容语义清晰有效；行数据由 C# 从包格子实时构造，UI 动态适配，无固定行数上限。

## 2. 实现原理（原生机制实证）

与 BackpackExpand 同架构，差异在**目标名单机制**（详见 `ModShared\README.md` 与 BackpackExpand DESIGN §2）：

- 改写 `ConfigManager._Config_Bag_Dict` 内名单条目的 `Size`（三层实时直读）+ `_bagSizeSet` 置 null 重建白名单；
- 5 秒轮询幂等改写（防读档/切场景表重载覆盖）；
- 本 mod 不动 Burden（柜子负重由 CabinetBurden 管）。

### 名单 = 自动发现 + 黑名单（2026-10-13 统一化，同日并入冰箱扩容）

- **自动发现**：扫 `Config_Furniture` 全部 `BagId>0`（不限 FurnitureType——Type=0 里有大量原生家柜：床头柜 110003/衣柜 110004·110006/材料架 110009，实证 FurnitureType 不可靠）。
- **分组**：包的全部使用家具都是冷链电器（`IsElectrical && ElectricalType==1 && ColdRate>0`，与原生 CollectFridges 同判定）→ **冰箱组**（FridgeWidthMult/FridgeHeightMult 倍数，自动兜住未来新冰箱，如 2026-10-08 大容量冰柜 115005 那类）；其余 → **柜子组**。注意不能按"有任一冷链家具"分组——110001 与冰箱 66113 共包，但置物架/工具柜不是冷链，仍归柜子组。
- **黑名单 `DefaultExcludeIds`（34 包）**：见 §5，对两组都生效。
- 优先级：ExtraIds（cfg，按冷链属性加回对应组）> ExcludeIds（cfg，两组都排）> DefaultExcludeIds > 自动发现。
- 优点：**游戏更新新增柜子/冰箱自动跟上**，不再依赖手动补名单（原 FridgeExpand 静态名单漏大容量冰柜的事故类别根除）。

### 载具组发现（2026-10-18 新增，反汇编+运行时双实证）

- **后备箱**：枚举 `ConfigManager._Config_Vehicle_Dict` 全部行取 `TrunkBagId`（档位 1 自行车/2 轿车/3 SUV，`VehicleConfig.GetTrunkBagId(grade)` 反汇编实锤 grade∈[1,3] 才查表、grade 0 购物车时代返回 0 无后备箱）→ 新车自动跟上。**车表随对局世界加载（主菜单阶段为空）**，Ticker 就绪首轮打"载具组补录"名单行；1023 种子不受影响恒生效。
- **门口塑料袋**：`VehicleConfig.DoorBoxBagId=1023` 常量镜像进代码。**运行时实锤包 1023 名="SUV后备箱"（原生 12x10）**——门口袋与 SUV 后备箱共用此包（12x10→18x15 已生效）。家具 1024 在家具表的默认 BagId=2003 是纸箱/睡袋/血袋等场景共用包（黑名单成员，不扩）；门口袋系统走 1023 专用绑定。
- 撞号防御：载具包若同时命中家具发现则归载具组并记日志（当前实证无撞号，纯保险）；ExcludeIds 对载具组同样生效。

### 关键实证：家具名 ≠ Bag 表名（v1.3.0 定案，统一化的直接动因）

- 游戏内叫"工具柜"的家具 70006，实际用 **bag 110001**——与"中型置物架"**共用同一个包**；
- 置物架家族：小型=110002（另有 80032/80121 系"小型置物架"用 **bag 1001 柜子1**）、中型=110001、大型=110000、超大型=110008、材料架=110009；
- **v1.1.2 白名单（8 包）只有 110001 在置物架家族内 → 中型 8x10→12x15=180 格反超大型原生 12x10=120 格**——用户反馈"大型置物架反而比小型格子少"的根因；同理 1001（柜子1）没进名单而 1002/1003 进了。统一 ×1.5（AwayFromZero 取整对每维严格单调）恢复家族内大小排序。
- **id 撞号陷阱**：bag 10002=金属柜，家具 10002=小型置物架（用 bag 110002）——玩家自查加 id 极易加错，cfg/README 要写清。

### 3.1 视口适配守卫 ViewportFit（2026-10-16，ViewportProbe 三轮实测驱动）

现象：切到大柜子页签（超大型置物架 15x12→23x18）时烹饪界面右侧菜谱栏被切出屏幕。根因链（全部实测）：
- 用户真实 CSS 视口 **1536x864**（4K 密度 2 再乘 0.8 系数；官方 MaterialRack 注释"864 视口"即此，勿按 1920x1080 估算）；
- 面板根容器是 body flex 的子项：内容 max-content 超可用宽度时**容器被压到可用宽度**（子项 min-content 保护的是"不缩到内容以下"，但容器宽度本身被 flex 布局封顶），内部各栏装不下向右**顶出容器**；
- 官方 `createViewportFit` 量容器 `offsetWidth`（同样被封顶）→ 顶出的部分测量不可见 → 按"装下了"缩放 → 右栏留在屏外。实测：cooking-system 视觉右边界 1519（在内），right-panel 视觉右边界 **1564**（超视口 28px）。

两把工具（每 2s 巡检 + iframe load 即时钩子 + 容器 MutationObserver，Root 上下文经 `ExecuteJavaScript` 执行，同源直读 iframe DOM，**不注页面脚本**；动作日志 `[CEVF]` 走 Root console → Player.log——2026-10-16 游戏更新后转发方向已翻转为 Root 转/iframe 不转）：
- **A 工具（12 个官方适配页）**：注入 `<style id="__CEVF_STYLE">` 写「根容器 `flex-shrink:0 !important`」——根容器不再被挤压 → 官方自己的测量看到真实宽度 → **缩放仍由页面自己算自己管**。另做"欠缩桥接"：按官方同公式（同选择器 offsetWidth/Height + 按页 margin，MARGINS 表）补写正确缩放（页面首次适配早于样式注入时救场，页面下次重算自然收敛）。按页照抄官方 heightProp（HPROPS 表：Compressor/MaterialRack/Shredder/ToolTable 用 height，其余 minHeight）——写错属性会与官方身高补偿打架出竖向滚动条（v3 实测教训）。
- **LockFit（BrewPanel/DyePanel/RatCage 三页，v14/v15 终版）**：往页面注入【官方锁的纯累计复刻 + 官方 `createViewportFit` 调用】脚本（页面上下文）。根因：官方 `createGridSizeLock` 的 seenCols **有服务端 maxCols 提示时无视历史累计**（`hintC ? max(hintC,cols) : max(seen,cols)`）——这三页提示疑随页签变导致锁失效（烹饪的提示是真·常量最大值所以原生稳定）。复刻版纯累计（`max(seen,cols)`），在页面 message 监听里**同步**重写格子外边距（页面自己的 listener 先注册先执行、我们后写=生效且无闪帧），再调官方 fit。v15 加**初始即最大**：`BootstrapJs` 属性把受管包最大宽高（ManagedMaxW/H，封顶后由 CabinetTicker 每轮刷新）填为 seenC/seenR 初始值 → 打开即最大柜子尺寸、永远恒定（对齐烹饪/工作台）。取舍：站点只连小柜子时也按最大预留留白（与官方页访问过大柜子后的观感相同）。TrapUI 跳过（#app 是 display:contents 无可测根容器）。
- **MaxCols 宽度封顶（C# 侧，v1.3.4 起）**：材料架 20 列×1.5=30 是全游戏唯一异类，让每个界面多一档缩放。默认封 23（=超大型置物架）后全部柜子页签同宽、缩放统一。实现：PartitionByCap 按"投影宽度>cap"分流，超限包不进共享 RewriteSize（避免每周期 23↔30 来回改写刷日志），走本地 CappedRewrite（NativeW/NativeH 本地缓存原生值，幂等）。
- **v5~v12 自制锁定机制已全线拆除（2026-10-17，用户四小时实测反馈驱动）**：曾用 min-width 锁复刻官方尺寸锁（根容器/格子/栏位/持久状态/消息中继），五轮翻车，教训沉淀：①测量含被自己写入样式影响的元素=反馈循环（无限缩小）；②className 做锁定键，兄弟共类名则互相污染（酿酒桶三栏全胖、老鼠笼黑块）；③只在"新值>记录"时写样式，页面重开（DOM 重建）后永不恢复；④观测最快 150ms/帧且去重，与用户 60fps 肉眼不可对齐，黑匣子（CEVFBB）只能证伪不能证实。**结论：能走官方机制就不自制；确需自制时，锁定键用结构序号、样式写入要幂等恢复、验证要么逐帧采样要么开 CDP 远程调试。**

铁律：**BackpackUI/TradeUI 永不触碰**（自带 applyViewportFit 且拖拽补偿是私有 `clientX/viewportZoom` 变量，外人设缩放必错位）；B 工具安全性依据=createGridBag 族坐标换算自动除以 `getBodyZoom()`（body 计算缩放），外部设 zoom 天生被补偿。

取证工具：一次性探针 mod `SurvivalLog.ViewportProbe`（仓库留存，不进套件；三关校验 `tools\vpp_check.js`）；诊断结论详见记忆 webui-viewport-fit 相关条目。

### 诊断钩子的三代演进（都是实锤，复用前必读）

1. v1：patch `Ac_ToolTable_Open.SendAction`（泛型 List 参数）——挂载成功但**从不触发**（interop 泛型坑第二次实锤）；
2. v2：patch `Reducer_Web_ToolTable.Trigger_RA_Open`——同样不触发（根因：界面根本不走 ToolTable）；
3. v3（现行）：patch **实例方法** `BagComponent.OnInit`——实测可靠，读档即打印全部容器清单，一轮定位。
   结论：**patch 静态方法/带泛型参数的方法不可靠，实例方法可靠**（与旧 mod get_StackLimit getter 先例一致）。

## 6. 与原生 / 其他 mod 的交互

- **单写者原则**：合并后全游戏只有本 mod 写家具包的 `Config_Bag.Size`（BackpackExpand 只管玩家背包链 1-11，与家具发现天然不相交）——旧"两 mod 共管一个包 ×1.5×1.5=×2.25 双乘"风险类别整体消除（BagTable 原值快照 OrigW/OrigH 是进程内字典，双写会互相污染原值，此为当初必须拆名单的根因）。
- FridgeChill 只改 `Config_Furniture.ColdRate`（保鲜倍数），与本 mod 的 Size 改写零冲突；其名单仍是静态 {1004,115000,115001,3002,115005}，未来新冰箱需手动补（独立事项）。
- 110001 与置物架/工具柜/大量场景家具（医疗器械台/货堆/药品柜等）共用包：扩 110001 全部共用者一起变大——共用包的固有属性，场景侧只影响搜刮容量，无害。
- 不写存档、不碰物品；卸载即还原（扩容区物品由 SetBagPosSafe 坐标矫正自动挪回）。

## 7. 已知限制

- 共用包无法只放大单一家具（110001 工具柜⇄中型置物架；1001 柜子1⇄场景贩卖机/轿车 90030 等）。
- 纸箱族（1010/2003）因与工具桌/载具共包被整体排除，家里放的纸箱不扩容（用户拍板；要加走 ExtraIds）。
- FridgeChill（保鲜）的 BagId 名单仍是静态 {1004,115000,115001,3002,115005}，未来新冰箱保鲜需手动补（与本 mod 的格子扩容互不影响）。
- 门口塑料袋数量上限 2 个不扩（用户拍板 2026-10-18：存档 schema 深度固化，扩格子已达成目的）；若未来版本把门口袋改绑 2003 等其他包，日志 `[门口袋核对]` 行会提示（届时人工定夺）。
