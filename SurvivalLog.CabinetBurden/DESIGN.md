# 柜子负重解放 CabinetBurden — 设计文档

> 本文档随源码存放在 mod 自己的文件夹内；**每次迭代改动必须同步更新本文档**
> （文档维护规则见 `docs\00-目录说明.md`）。
> 版本：跟随套件 version.json；机制与实证结论长期有效。
> 验证于 gamekb：`2026-10-23_26157732`（游戏 buildid 26157732 / RuntimeAssets 1.1.19611，实机全绿）

## 1. 功能定位

解除储物家具的负重限制：橱柜、床头柜、衣柜、纸箱、储物柜、金属柜、置物架、冰箱、箱子等
"格子没满却放不进去"的现象。默认把全部储物包的负重上限 ×1000（等于实际解除），可 cfg 调倍数。

不改存档、不改游戏文件，删 dll 即还原（负重快照下次读档回到原生值）。

## 2. 实现原理（2026-10-11 反汇编实证，GameAssembly 当日版）

### 2.1 负重链路（逐指令验证）

- `Config_Furniture` **没有任何负重字段**（interop 全字段核对）——家具容器负重上限唯一来源是
  `Config_Bag.Burden`（偏移 0x30），与玩家背包同表。
- `BagComponent.OnInit(bagConfigId)`（RVA 0x2e2ec10）：查 `_Config_Bag_Dict` →
  `mov eax,[rax+30h]`（Config_Bag.Burden）→ 存入自身 0x44 快照字段；0x58/0x5C 置 -1.0f。
  `SetBagConfigId` 同样重读快照（换包语义）。
- `GetMaxBurden`（0x2e2ea20，与 GetTotalBurden 同地址）：
  `Round((Burden快照 + ExtraBurden) × (1 + GetHeavyLoadRatio) + GetBurdenFlatBonus)`。
  两个加成项都按 ownerId 走 AE/状态管线（0x2e2e970/0x2e2e8c0），家具容器查不到恒为 0
  → **改基础 Burden 即完全主导结果**。
- 放入总闸 `ItemManager.TryAddItemToBag` → `CanAddWeight(w)`（0x2e2e610）：
  `当前重量[0x40] + w <= GetMaxBurden()`；E8 扫描另 4 个调用方均为家具收成/取回阻断提示
  （酿酒收获/压缩机/退燃料/粉碎机），同一判定，无第二套家具负重路径。

### 2.2 改写方式

- 复用套件已验证的内存表直写机制（同 BackpackExpand 负重×2）：5 秒幂等轮询，
  进程内首读值记为原值，永远按 `原值 × BurdenMult` 写回；cfg 改动即触发重跑。
- 名单**自动发现**：扫 `_Config_Furniture_Dict` 全部 `BagId>0` 的家具（不限 FurnitureType：
  Type=2 可放置储物 + Type=0 原生/场景固定柜如床头柜、纸箱、衣柜），收集去重后的 BagId，
  套 Include/Exclude。游戏更新新增柜子自动生效（2026-10-08 大容量冰柜漏网教训）。
- **故意不复用** `BagTable.RewriteBurden`（需要全量名单日志 + 0/1 停用语义 + 防溢出上限，
  且避免动 ModShared 共享源——改动需同步 4 份扩容文档）；只用其 `Cm/FurnDict/BagDict/ParseIds/Name` 原语。
- 防溢出：写值封顶 5 亿（GetMaxBurden 内 float 中间量取整回 int，×1000 后最大仅千万级，余量充足）。

### 2.3 生效时机（快照语义）

- 负重是 OnInit/SetBagConfigId 快照：**改表需重新读档**才对已存在容器生效
  （插件随游戏启动加载、轮询在读档前完成改写，正常流程开机即生效）。
- 新制作/新放置的家具 OnInit 时读改写后的表，立即生效。
- 格子数量不受影响（Size 不动，归扩容 mod 管）。

## 4. 配置项（com.local.survivallog.cabinetburden.cfg）

| 键 | 默认 | 说明 |
|---|---|---|
| BurdenMult | 1000 | 负重上限倍数；1=还原原生；≤0=停用改写 |
| IncludeBagIds | 空 | 追加 BagId（工作台抽屉 5010/5012/5013、购物车 3、轿车 4 要解放就加这里） |
| ExcludeBagIds | 3,4 | 排除 BagId（优先级最高）。默认排除载具包 |
| ListOnReady | true | 首次生效时日志列出全部受管储物包（核对名单用） |
| Verbose | false | 每轮明细 |

## 5. 范围取舍（用户 2026-10-11 确认）

- **覆盖范围 = 全部储物家具**（自动发现，非仅原生柜；实测名单见 §8——其中冰箱/置物架等
  Burden=0 天然跳过，自动发现保证未来新增加负重的容器也被覆盖）。
- **幅度 = ×1000**（保留 UI 数字量级，格子满之前不可能触顶）。
- 默认排除：购物车 3、轿车 4（载具包，BagExpand 系一贯不动）；工作台抽屉 5010/5012/5013
  （扩容 mod 时期用户已明确撤销抽屉范围，本 mod 沿用，要开自行 Include）。
- 原生柜与玩家可造的同名柜共用同一条 Config_Bag——按"柜子种类"一起生效，无法也无需区分。

## 6. 与原生 / 其他 mod 的交互

- 与 4 个扩容 mod 零冲突（一个管格子 Size，本 mod 只写 Burden；玩家背包链 1,2,5-11
  不被家具引用，天然不在名单内，与 BackpackExpand 负重×2 的目标集不相交，无双重倍乘）。
- 与 CabinetEverywhere 零冲突（页签注入不碰负重）；其"柜子页签无负重语义"的界面
  （制作取料等）本就吃不到限制，本 mod 改的是直开柜子的放入检查。
- UI：柜子界面的负重量示会显示 ×1000 后的上限（如 500 → 500000），属预期。
- 玩家自身超重 debuff（CheckOverweightBuff）走玩家背包，不受影响。

## 7. 已知限制

- 已存在容器需**重进存档/重开游戏**一次才体现新上限（快照语义，安装后首次启动即完成）。
- BurdenMult 改回 1 可还原原生，同样需重读档才对已存在容器生效。
- 名单按 BagId 生效：若某家具与载具/装备共用包（现状仅购物车/轿车，已默认排除），
  排除名单兜底。
